# MHXX Hub — 装備検索とお守り

公開入口: https://snowman74-64.github.io/chappy-playground/mhxx/

既存の `/mhxx-palico/` と保存APIは維持します。新機能は静的HTMLとES modulesだけで動作し、AI APIや外部の装備検索サービスには接続しません。

## 使い方

1. 「お守り」に所有している護石の系統・ポイント・スロットを登録します。画像読取は未実装です。
2. 剣士／ガンナー、性別、進行度、武器スロット、必須・希望スキル、最低防御を指定して検索します。
3. 装備・発動スキル・部位ごとの装飾品配置を確認します。探索途中の場合は画面に表示します。

**お守りはブラウザの端末内保存です。** 端末間同期はありません。JSON書き出し／読み込みで移行できます。初期ライブラリは空で、サンプル護石を所有品として扱いません。Nodeでは `charm-library/charms.json` またはqueryの `charms` を読みます。ブラウザの保存内容をNodeから自動取得することはありません。実物の護石をGitへコミットする必要はありません。

## 自然言語から呼ぶ

LLMは条件を次のJSONへ変換し、候補そのものを推測せずソルバーを呼びます。

```json
{
  "hunterType": "blademaster",
  "weaponType": "SwordAndShield",
  "gender": "male",
  "rank": "G2",
  "weaponSlots": 0,
  "requiredSkills": ["弱点特効"],
  "preferredSkills": ["業物"],
  "excludedSkills": [],
  "minDefense": 500,
  "useCharmLibrary": true,
  "maxResults": 20,
  "maxNodes": 250000
}
```

Node API:

```js
import { solveArmor } from './mhxx/solver/api.mjs';
const response = await solveArmor(query);
// response: {results, complete, warnings, searchedCombinations,
//            visitedNodes, candidateCounts, elapsedMs}
```

CLI: `node mhxx/scripts/solve.mjs query.json`。引数省略時は標準入力からJSONを読み、標準出力へJSONを返します。不正な条件は非ゼロ終了です。

ブラウザでも同じ `api.mjs` をimportできます。UIはWeb Workerで探索します。Workerへは `{id,query}` を送り、`{id,response}` または `{id,error}` を受け取ります。Workerには `charms` を明示的に渡します。停止ボタンはWorkerを終了し、次回検索時に新しく作成します。

`weaponType` は剣士／ガンナーの推定と整合確認に使用します。`weaponSlots` は実際に使用する武器の確認済みスロット数を指定してください。任意の `weaponId` 指定時は武器の解禁条件とスロットを検証します。武器カタログはハンターナイフ系統11段階の最小サンプルで、全武器データベースではありません。LV1以外の解禁ランク10件は未確認として検索から除外します。

## 正確性の境界

- MHXXのポイント制を計算します。上位の見切りなどは同系統の下位要求も満たします。最終発動一覧には各系統の最上位だけを表示します。除外スキルも閾値の方向を考慮します。
- 防御条件は**全防具の初期防御合計**です。最終強化防御はデータとして保持しますが、進行度ごとの強化上限が未確認なため検索には使用しません。
- ランクはAthenaの集会所条件を正規化します。村クエストのみ・追加の村条件・未確認の解禁条件は保守的に除外します。素材所持、依頼クリア、個別クエストの完了まで保証するものではありません。
- 装飾品は頭・胴・腕・腰・脚・武器・護石の7容器に別々に配置します。1スロットの部位を3つ集めても3スロット珠を配置できません。負のポイントも合算します。
- 胴系統倍加は胴防具と胴の装飾品に適用します。複数部位の倍加は加算です。
- 秘術／護石強化および複合スキルを含む防具1,005件は今回未対応として除外し、警告を返します。特殊効果を無視して偽の成立結果を返しません。複合スキル67系統の定義は保持しますが、内包効果を単独スキルの要求に読み替える検索は行いません。
- イベント・闘技大会装備は既定で除外します。条件を別途確認した場合だけqueryで `allowEventEquipment:true` / `allowArenaEquipment:true` を指定できます。
- 護石は系統・整数ポイント・最大2系統・最大3スロットを検証します。登録値が実際に生成可能かというスキル順・護石種別・同時組み合わせの完全検証はしません。
- 同じ防具・護石セットの装飾品違いは、指定条件で最良の1配置を表示します。

## 探索方式と制限

部位別の候補を進行度・性別・剣士／ガンナーで絞り、**全スキルポイントが同じ**装備だけ防御・スロット・解禁ランクによる支配除去を行います。負スキルを落としたベクトルで誤った支配判定をしません。

残り部位の最大防御・必要スキルの楽観的上限・装飾品の最大効率で枝刈りします。装飾品は各容器の構成をキャッシュし、残り容器で達成できるポイント上限から再度枝刈りします。希望スキルは除外条件にしません。

ソートは希望スキル達成数、防御、空きスロット、装飾品数、解禁ランク、安定したID順です。数値スコアは内部用途で、画面は事実に基づく特徴を表示します。

既定の上限は25万探索ノードです。時間ではなくノード数で停止するため、同じデータとqueryは同じ順序を返します（`elapsedMs`を除く）。`complete:false` は探索途中です。結果が空でも「存在しない」と解釈しないでください。返された候補は全て条件検証済みですが、全候補内での最適性は保証されません。`maxNodes` は最大1000万まで指定できます。`complete:true` でも対象データ・対応効果・支配除去後の探索範囲内の完了を意味します。

## データと再生成

データ出典・固定コミット・ハッシュは `canonical-data/sources.json`、取り込みの詳細は同ディレクトリのREADMEを参照してください。

収録: 防具6,025件、スキル327件（通常発動326件＋胴系統倍加の特殊定義）、系統205件、装飾品242件、武器11段階。主出典は [AthenaADP/MHGU-ASS 固定版](https://github.com/AthenaADP/MHGU-ASS/tree/ae7f125d1d381278d15908d7ce5b092076423918)、武器は [MHXX Kiranico](https://mhxx.kiranico.com/buki/40b60)。日本語MHXXデータを取り込み、MHGU英訳・コラボ名へ置換しません。

未確認・低信頼: 防具526件と装飾品1件はランクだけで解禁を確定できないため除外。LV14金雷公ガンナー5部位は出典の防御値が176→104と逆転しており、`rawDefense` を保持して `defense` をnull、`confidence:low`、`invalidData:true` にしています。武器10段階の解禁ランクも未確認です。件数は重複区分を含みます。

## G2検証例

`examples/g2-query.json` をCLIへ渡すと、武器スロット0・護石なしでも弱点特効＋業物、初期防御550・空き1の途中候補を検出します。例はヴァイクX頭／ザザミXR胴／ギザミX腕／ヴァイクX腰／GXギザミ脚、痛撃珠【1】を頭・腕・腰に各2個、痛撃珠【3】を胴に1個です。**AthenaのG2条件に基づく候補**であり、R装備の解放依頼やGX装備の追加条件など、個別の作成条件は別途確認してください。

初回ローカル検証では約0.5秒、25万ノードで134防具組み合わせを装飾品込みで照合しました。`complete:false` の途中結果です。スマートフォン実機の性能保証ではありません。テストは候補を防具・珠から再計算し、スロットとスキルと防御の一致を確認します。

- `node mhxx/scripts/import-armor-data.mjs`: 固定コミットのAthenaデータを正規化。
- `node mhxx/scripts/import-weapons.mjs`: MHXX Kiranicoのハンターナイフ系統を抽出。
- `node mhxx/scripts/validate-data.mjs`: ID・型・閾値・出典参照・解禁ランクを検証。
- `node --test mhxx/test/*.test.mjs`: fixture、独立全探索との照合、本番G2検索を検証。
- `node --test mhxx-palico/scripts/*.test.mjs`: 既存のオトモ機能を検証。

ローカルでリポジトリルートをHTTP配信して `/mhxx/` を開きます（例: `python -m http.server 8080`）。`file://` での画面利用はWorker/fetchの制約により非対応です。GitHub Pages workflowもデータとソルバーのテストを実行します。
