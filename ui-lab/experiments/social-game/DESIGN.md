# 星環クロニクル攻略室：共通設計

## Reference

特定サイトの複製ではない。架空のスマートフォン向けターン制RPG「星環クロニクル」の非公式攻略・コミュニティサイト。実在のゲーム、運営、人物、課金サービスとは無関係。共通データとオリジナルSVGを使う。

## Intent

プレイヤーが「今やること」「所持キャラの使い方」「攻略で詰まった疑問」を短時間で見つけ、掲示板で相談できる。ビジュアルの期待感と、攻略情報の一覧性を両立する。サイト名は「星環クロニクル攻略室」。仕様上はローカルデモである。

## Visual DNA

天文・遺跡・魔導技術を題材にした世界観。本文は明るい紙面、濃紺のヘッダー、青緑の操作色、金色の小さな強調を候補とする。大きな広告風ヒーローで攻略入口を押し下げない。見出しとボタンは画像の細部から分離し、文字の背景が安定する配置にする。

キャラやイベントの画像は遷移先を予告する役割を持つ。画像を全て背景扱いにしない。攻略一覧はタイトル・対象・更新日を読み比べやすく整列し、掲示板は投稿本文を中心に組む。重い影、過剰な角丸、装飾の反復を避ける。レイアウトの答えそのものは固定しない。

## Tokens

候補色：背景 #f4f6f8、紙面 #ffffff、本文 #172638、補助 #536477、濃紺 #12243a、操作 #087e8b、アクセント #b57d20。本文16px目安、補助14px目安。主要操作は44px程度の押しやすさ。1440×1000と390×844を主要比較サイズとし、820pxでも破綻させない。意味は色だけで伝えない。フォーカスを明瞭にする。

## Layout Anatomy

共通データは fixtures/content.json。属性は火・水・風・光、役割は攻撃・支援・防御、レア度はSSR/SR。編成は4枠、同じキャラを重複採用できない。ゲーム内日程は固定データの日付を表示し、実時間によって終了判定を変えない。

| 画面 | 必須内容と行動 |
| --- | --- |
| トップ | 更新情報、開催イベント、初心者導線、キャラ/攻略/掲示板への入口、検索 |
| キャラ図鑑 | 12体の画像・属性・役割・レア度。複合絞込み、名前検索、名前/評価順ソート、件数/0件/リセット |
| キャラ詳細 | 同じデータの能力・スキル・育成素材・編成相性。図鑑/編成への導線 |
| 攻略一覧・詳細 | 8記事、カテゴリ絞込み、本文・更新日・目次・関連キャラ。ブックマーク切替 |
| イベント詳細 | 期間、報酬、攻略ポイント、関連記事。3件分 |
| 編成ツール | 4枠への追加/削除、重複/満員の説明、編成の共有URLと直接復元。コピー不可時は選択可能なURL表示 |
| 掲示板一覧 | 6スレッド、カテゴリ・検索・新着/返信数順、投稿件数。新規スレッドへの導線 |
| スレッド詳細 | 親投稿、返信、件数、新規返信。自分の投稿だけ編集/削除可能。他人の投稿は通報デモ |
| スレッド作成 | カテゴリ、タイトル、表示名、本文の入力→確認→修正→投稿。未入力/上限の説明 |
| 保存一覧・案内 | ブックマーク一覧、掲示板利用ルール、プライバシー、デモデータ初期化 |

ヘッダーに主要ナビとサイト内検索。検索はキャラ・記事・スレッドのタイトルと本文を対象にし、検索語、種別、件数、0件を表示。各詳細に独立URLを持たせる。ハッシュ方式も可。戻る/進む・直接URL・存在しないIDに対応。フッターに架空デモ表示・利用ルール・素材出典。

## Interaction / Motion

投稿タイトル1〜80文字、表示名1〜24文字（返信時の空欄は「名無しの旅人」）、本文1〜1000文字。空白のみは無効。入力内容はHTMLとして解釈せず文字列で表示。確認から戻っても保持する。削除は確認・取消可能。自分の投稿の判定はローカルデモ内の所有者IDであり、実認証ではない。

新規投稿・返信・編集・削除・ブックマークを専用名前空間のlocalStorageへ保存し、再読込でも維持する。共有シードは書き換えず、追加・変更差分を管理する。保存拒否や破損時は復旧可能な説明と一時利用を提供する。初期化はこのデモの保存キーだけを確認後削除する。通報は実送信せず、選択・確認・デモ完了を示す。モバイルメニューはEscapeと遷移後に閉じる。

## Constraints

HTML/CSS/JavaScriptによる既存UI Lab方式。ビルドや新規依存の導入を前提にしない。実サーバー、ログイン、課金、実際の投稿共有、外部送信は実装しない。シードデータの数値は実験用でありモデルが勝手に変更しない。補助文章は追加可能。画像追加生成・外部取得は実行中に行わない。各案のDESIGN.mdは共通設計へのリンクと実装判断のみを記載する。

## Adaptation from reference

学校実験の改善仮説を、情報密度の高い攻略・掲示板で試す。第一画面の文字と画像の分離、画像による遷移先の予告、状態保持を重視する。モデルやハイブリッド構成は未指定。途中レビューの有無は次セッションの実験条件で決め、全案に同じ条件を適用する。
